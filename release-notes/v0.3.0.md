# v0.3.0 — Drafts, attachments, labels, new mail and a safer server for LLMs

The biggest release so far. protonmail-mcp now has 29 tools (up from 16), MCP resources with subscriptions, prompts, and new-mail notifications over IMAP IDLE. It was also hardened for being driven by a language model: email content is treated as untrusted, deletion is recoverable, and an operator can limit what the model may send. More than a hundred bugs were fixed after a systematic review against a real ProtonMail Bridge.

**This release has breaking changes.** Read the upgrade notes below before upgrading from 0.2.0. The full list of changes is in [CHANGELOG.md](https://github.com/mattias242/protonmail-mcp-server/blob/v0.3.0/CHANGELOG.md).

## Highlights

- **Drafts as the safe way to "send"**: `create_draft`, `create_reply_draft`, `create_forward_draft`, `update_draft` and `send_draft`. Drafts are real Proton drafts that you can review and edit in Proton's own apps before anything goes out.
- **Attachments**: read them with `get_attachment` and send files with `send_email`, `reply_to_email` and `forward_email`. All file access stays inside one directory (`PROTONMAIL_ATTACHMENT_DIR`).
- **Labels, stars and bulk operations**: `add_label`, `remove_label`, `flag_email` and `unflag_email`. The flag, move, delete and label tools accept up to 100 UIDs per call.
- **Better search and conversations**: filters on recipient, Cc, body text, star, answered, size and attachments; words with å, ä, ö are found; `get_thread` returns a whole conversation.
- **New mail**: IMAP IDLE on dedicated connections, the tools `check_new_emails` and `wait_for_new_email`, and resource notifications for watched folders.
- **MCP resources, subscriptions and prompts**: `mailboxes://`, `mailbox://{mailbox}` and `email://{mailbox}/{uid}`, notifications after new mail and after every write tool, and four prompts for common tasks.
- **Operator controls**: read-only mode, draft-only mode, a recipient allow-list, limits on recipients per send and sends per hour, and an audit log of every send and write.
- **Built for LLM clients**: MCP tool annotations and titles, server instructions, and actionable error messages that tell the model what to do next.

## Upgrade notes

- **Python 3.12 or newer** is required.
- **Pass `mailbox` with every UID.** UIDs are only unique within one mailbox, so all tools that act on a UID now require the mailbox it came from (every response that contains a UID also contains its `mailbox`). Listing and search tools still default to `INBOX`.
- **`delete_email` moves to Trash.** Permanent deletion needs `permanent=True` with `mailbox="Trash"` (or `Drafts`).
- **New response formats**: `search_emails` returns `{"mailbox", "messages", "total", "has_more", "complete", "note"}`; `list_mailboxes` returns `type` (`system`/`folder`/`label`/`container`), `selectable` and `special_use`; bulk calls return `{"ok", "failed"}`; `get_email_headers` uses `message_id` and `reply_to`.
- **`body_html` is `null`** unless `body_format="full"`; check the new `has_html`.
- **Mailbox names are readable** (`Labels/Näs`, not modified UTF-7). Pass them back exactly as `list_mailboxes` returns them.
- **Errors instead of empty answers**: a missing UID or a refused IMAP command raises an error instead of returning `null`, `false` or an empty list.
- **Reading no longer marks email as read**: `get_email` now uses `BODY.PEEK`; call `mark_email_read` explicitly.
- **Replies quote the original** unless `quote_original=False`.
- **New start-up side effects**: one IMAP IDLE connection per watched folder (INBOX by default) and the attachment directory `~/Downloads/protonmail-mcp` is created.
- **Folder tools** require a `Folders/` or `Labels/` prefix, and `delete_folder` refuses a non-empty folder without `force=True`.
- **Sending is limited by default** to 50 recipients per send and 30 sends per hour (`PROTONMAIL_MAX_RECIPIENTS`, `PROTONMAIL_MAX_SENDS_PER_HOUR`; `0` disables a limit).
- **Integration tests are opt-in**: `uv run pytest` runs only the unit and BDD tests; use `uv run pytest -m integration` for tests against a running Bridge.

## Security

- Fixed: a failed SELECT left Bridge in the previous mailbox, so a misspelt mailbox name could change or delete a message with the same UID in another folder.
- Fixed: `delete_email` and `move_email` could permanently expunge other messages in the folder; moves that Bridge turns into permanent deletion are now refused or skipped.
- Fixed: IMAP command injection through search parameters.
- New: protection against prompt injection — invisible and misleading Unicode characters are removed, hidden HTML text is left out, content is marked untrusted, and typical injection phrases are flagged. Addresses with hidden characters are shown with visible codes and refused as recipients.
- New: the attachment directory refuses path traversal, symlinks, hard links, swapped files and anything that looks like a secret (SSH and GPG keys, `.env`, private keys).
- The Bridge password is masked in all errors and logs, and recipient addresses (including Bcc) are kept out of stderr.
- Crafted emails can no longer make parsing take quadratic time.
- Dependencies updated: `cryptography` 46.0.6 (CVE-2026-34073) and 50.0.0, `aiosmtplib` 5.1.2 (GHSA-vxj7-4xrp-5vr4; STARTTLS only, which Bridge does not use), `mcp` 1.28.1 and more (#4).

## Known limitations

- Body search (`text`/`body`) with å, ä, ö finds about 95 % of matches; words that quoted-printable wraps mid-word, base64-encoded parts and HTML entities are missed.
- Only new mail in watched folders (at most 5) is reported from other clients; flag, label, move and folder changes made elsewhere give no notification.
- High-water marks for new mail and the hourly send counter are kept in memory and reset when the server restarts.
- Prompt-injection protection reduces the risk but cannot remove it: `suspicious_content` is a heuristic warning, and homoglyphs are not caught. Keep a human in the loop for anything that sends, and prefer drafts.
- Validation errors for missing or wrongly typed parameters come from pydantic in English; all other errors are in Swedish.
