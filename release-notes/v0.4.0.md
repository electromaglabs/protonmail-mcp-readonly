# v0.4.0 — MCP Python SDK 2 and clear installation instructions

The server now runs on version 2 of the MCP Python SDK (`mcp>=2.3,<3`). For the model nothing changes: the 29 tools, their parameters and schemas, the three resources, the four prompts and the error messages are the same as in v0.3.1. A recorded contract of everything a client sees is identical before and after the switch, apart from an empty `experimental` capability that is no longer sent. The full list of changes is in [CHANGELOG.md](https://github.com/mattias242/protonmail-mcp-server/blob/v0.4.0/CHANGELOG.md).

## Install

You need [ProtonMail Bridge](https://proton.me/mail/bridge) running and signed in, Python 3.12 or newer and [uv](https://docs.astral.sh/uv/).

```sh
uv tool install --python 3.12 "git+https://github.com/mattias242/protonmail-mcp-server@v0.4.0"
```

Then add it to Claude Code, with your Proton address and the password the Bridge app shows (not your Proton password):

```sh
claude mcp add protonmail -s user \
  -e PROTONMAIL_USERNAME=user@proton.me \
  -e PROTONMAIL_PASSWORD=bridge-generated-password \
  -- /Users/<you>/.local/bin/protonmail-mcp
```

Claude Desktop, running from a clone, and troubleshooting are covered in the [installation section of the README](https://github.com/mattias242/protonmail-mcp-server/blob/v0.4.0/README.md#installation).

## Upgrade from v0.3.x

```sh
uv tool install --force --python 3.12 "git+https://github.com/mattias242/protonmail-mcp-server@v0.4.0"
```

Then restart Claude Desktop, or reconnect the server in Claude Code with `/mcp`. Your client configuration does not change. From a clone: `git pull && uv sync`.

## Behaviour to be aware of

- **Resource subscriptions** (`notifications/resources/updated`) work for clients on MCP protocol versions before 2026-07-28, which Claude Code and Claude Desktop use today. The 2026-07-28 protocol replaces them with `subscriptions/listen`, which this server does not support yet, so it does not advertise subscriptions to such clients. Tools, resources and prompts work on both protocol versions.

## Smaller changes

- Tool descriptions are the same on every Python version; on Python 3.12 they used to keep the docstring's indentation.
- A tool refused by policy (`PROTONMAIL_READ_ONLY`, `PROTONMAIL_SEND_MODE`) and a failing resource read no longer write a stack trace to the server log. The client sees the same text as before.
