# v0.3.1 — Installable without the lock file, and safer deletion and replies

A bug-fix release on top of v0.3.0. No tool parameters changed; two answers can look different (see *Behaviour to be aware of*). The full list of changes is in [CHANGELOG.md](https://github.com/mattias242/protonmail-mcp-server/blob/v0.3.1/CHANGELOG.md).

## Installation fix

v0.3.0 did not start when it was installed without the lock file (`uv tool install`, `pip install`): those installers pulled in mcp 2.x, which renamed FastMCP, and the server failed with `ModuleNotFoundError: mcp.server.fastmcp`. `mcp` is now limited to `<2`.

```sh
uv tool install --python 3.12 "git+https://github.com/mattias242/protonmail-mcp-server@v0.3.1"
```

## Fixes from a final review against a real Bridge

- **Permanent deletion tells the truth.** When Bridge answers `Code=2501`, it stops the whole batch and leaves the other emails in All Mail without a folder. Each email is now looked up in All Mail; if it is still there it is put back in Trash and deleted again, otherwise it is reported in `failed` with an explanation, never in `ok`.
- **The same email is recognised by Proton's own id** (`X-Pm-Internal-Id`) instead of Message-ID, date and size, which two different emails can share. This makes `move_email`, `delete_email`, `remove_label` and `unflag_email` act on exactly the email you asked for; `unflag_email` no longer removes the star from a look-alike email.
- **Nothing else stalls during a slow deletion.** The wait after `Code=2501` no longer holds the IMAP lock, so other tools and `wait_for_new_email` keep working.
- **Timeouts in clean-up steps** no longer turn a successful `unflag_email` into an error or throw away the result of a permanent deletion.

## Security

- **Replies to a forged "own" email go to the right place.** An email with your own address in `From` and a lookalike address in `To` was treated as one you had sent, so `reply_to_email` and `create_reply_draft` addressed the reply to the lookalike. An email now counts as yours only when Bridge marked it `X-Pm-Origin: internal` or the same email is in Sent.

## Behaviour to be aware of

- `unflag_email` with a single UID can return `{"ok", "failed", "note"}` instead of `true` when the star was removed but the Starred view could not be cleaned up.
- A permanent deletion that hits `Code=2501` can take about 50 seconds.
